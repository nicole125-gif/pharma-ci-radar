# 竞争事实内部验证执行手册

更新日期：2026-06-10

配套文件：

- `2026-06-internal-validation-backlog.csv`：需要回答的16项问题。
- `2026-06-internal-validation-execution.csv`：责任人、样本门槛和验收规则。
- `2026-06-internal-evidence-intake.csv`：证据收件与复核记录。
- `2026-06-competitive-project-log-template.csv`：真实竞争项目可比数据。

## 1. 执行目标

本手册用于把公开研究无法证明的价格、交期、产地、证书、装机和服务事实转成可审计的内部证据。它不用于收集未经授权的商业秘密，也不允许用个人印象替代项目文件。

每项结论必须经过以下链路：

```text
validation_id → 执行任务 → 原始证据 → 独立复核 → 样本门槛 → 结论 → 战卡或策略更新
```

## 2. 状态规则

### 待验证问题

| 状态 | 使用条件 |
|---|---|
| `OPEN` | 尚未分派或没有有效证据 |
| `IN_PROGRESS` | 已分派且正在收集证据 |
| `VERIFIED` | 已达到执行矩阵的最小样本数和验收规则 |
| `REJECTED` | 证据明确否定原假设 |
| `INSUFFICIENT` | 已调查但证据质量或样本不足 |

`REJECTED` 不代表调查失败。例如，两个同规格项目均未显示ESG价格优势，应记录为对“存在可重复优势”假设的否定证据。

### 单条证据

| 状态 | 使用条件 |
|---|---|
| `PENDING` | 已收件，尚未复核 |
| `VERIFIED` | 文件主体、日期、型号、范围和内容已核对 |
| `REJECTED` | 文件错误、过期、主体不符或与目标型号不匹配 |
| `INSUFFICIENT` | 文件真实，但不能独立支持目标判断 |

证据还要标记为 `SUPPORTS`、`CONTRADICTS` 或 `CONTEXT_ONLY`。反证必须保留，不能因不符合预期而删除。

## 3. 每周工作流

1. 产品经理从P0开始分派 `validation_id`，明确执行负责人和30天或60天窗口。
2. 收集人将原始文件存入受控目录，在证据收件表记录文件位置，不把敏感附件提交到Git。
3. 复核人检查主体、型号、配置、日期、市场范围和文件完整性。
4. 可比竞争项目同时填写项目日志，并用 `validation_ids` 关联一个或多个验证任务。
5. 双周P0复盘、月度P1复盘；只有达到样本门槛后才能更新backlog状态。
6. 战卡、价格策略或威胁等级的修改必须引用已验证项目或证据记录编号。

## 4. 角色访谈提纲

### 销售与销售运营

必须取得：

- 客户任务、项目阶段和决策单位是单阀、阀门包、功能模块还是完整回路。
- 双方具体系列、型号和完整配置，不接受只写品牌。
- 数量、币种、税费、折扣、贸易条款和报价日期。
- 客户前三项决策标准及其来源：客户原话、邮件、会议纪要或正式评分。
- 输赢结果和可验证原因；区分客户事实、销售判断和推测。

追问：

1. 对手赢的是产品、既有验证、价格、交期、关系还是总包责任？
2. 如果价格更低，规格、文件、执行反馈和服务是否完全相同？
3. 客户是否明确拒绝过某项技术或商业条件？

### 应用工程与产品经理

必须取得：

- 介质、温度、压力、压差、口径、连接、材料和清洗灭菌条件。
- 阀体结构、Ra、膜片或密封、排空、死区和失效位。
- 测量原理、标况、量程、精度定义、通信和校准条件。
- 对手型号是否属于制药卫生、半导体高纯还是通用工业能力线。
- “不可直接比”的字段及技术排除理由。

追问：

1. 哪个参数真正决定适用性，而不是目录中的醒目数字？
2. 单阀、阀块和完整回路的责任边界分别由谁承担？
3. 当前结论需要哪份图纸、数据表或验证文件才能升级？

### 供应链与采购

必须取得：

- 报价主体、订单主体、制造地、发货地和包装/铭牌信息。
- 标准品、常规生产和定制品分类。
- 承诺交期、实际出货、实际到货和延期原因。
- 现货、计划库存、项目备货或临时调货的区别。
- 关键膜片、执行器、电子模块和备件的补货周期。

追问：

1. “本地制造”具体覆盖哪个型号和哪道工序？
2. 交期优势来自库存、产能、进口路径还是销售承诺？
3. 同一优势能否在至少两个项目中重复出现？

### 质量与法规

必须取得：

- 证书或声明原件、发行机构、发布日期、有效期和文件版本。
- 适用型号、材料代码、生产地址和市场范围。
- 材质证明、Ra报告、膜片批次、泄漏/压力测试和批次追溯关系。
- FDA、USP、3-A、EHEDG、ASME BPE、EC 1935/2004各自证明的对象。

追问：

1. 文件证明的是材料、设计、工厂体系还是具体交付批次？
2. 网页图标能否追溯到当前型号和当前文件？
3. 文件变更后是否有客户通知和重新验证机制？

### 售后与服务

必须取得：

- 工单编号、城市、产品族、故障现象和影响等级。
- 首次响应、到场、备件满足和关闭时间。
- 根因、处理动作、是否复发及客户确认。
- 校准、维修、替换和现场工程分别由谁完成。

追问：

1. 慢在响应、诊断、备件还是客户停机窗口？
2. 该事件是单例还是产品族的重复模式？
3. 对手服务表现来自客户事实还是我方销售印象？

## 5. 四类证据验收

### 价格

只有双方型号、关键配置、数量、币种、贸易条款和证据位置齐全，才可形成价格比较。目录价、预算价、口头折扣和不同规格报价只能作为线索。

### 交期

承诺交期与实际交期分开记录。只有报价或订单承诺，不得写成实际交付能力；标准品与定制阀块不得混合统计。

### 认证与质量

网页图标和宣传文字不能替代原件。证书必须匹配主体、型号或材料代码、日期和适用范围；批次质量判断必须来自同一订单文件包。

### 输赢与客户认可

输赢结果必须有项目记录。原因优先采用客户邮件、会议纪要、正式评分或采购反馈；销售复盘可保留，但内部可信度不得高于中等。

## 6. 结论升级门槛

满足以下全部条件后，才可把backlog状态改为 `VERIFIED`：

1. 已达到执行矩阵的 `minimum_verified_records`。
2. 每条证据均为 `VERIFIED`，并记录复核人和日期。
3. 样本符合 `acceptance_rule`，没有用不合格样本凑数量。
4. 结论范围不超过证据范围，例如两个BNW型号不能代表全部Fujikin卫生阀。
5. 反证、例外和区域差异已写入结论。
6. 输出已进入执行矩阵指定的 `decision_output`。

价格、交期、服务和市场采用率至少每季度复核；证书在版本、材料或有效期变化时立即重审。

## 7. 保密与文件管理

- Git中只保存索引、摘要和非敏感模板，不保存客户名称、报价附件、PO、合同、工单或证书受限副本。
- `file_location` 使用公司批准的文档库路径或记录编号。
- 客户和项目名称可按权限匿名化，但内部应保留可审计映射。
- 未经授权不得获取或传播对手保密文件；仅使用合法获得的项目资料、客户反馈和供应商文件。

## 8. 首轮30天安排

### 第1周

- 分派全部P0任务。
- 从最近12个月项目中筛出至少10个候选记录。
- 取得Bürkert四个重点Type的ERP/订单证据。

### 第2周

- 完成双方配置归一化。
- 优先收集GEMÜ卫生阀/阀块、Fujikin MFC/卫生阀、ESG标准阀各2个候选项目。
- 质量团队启动ESG证书和批次文件审查。

### 第3周

- 供应链核对产地、承诺与实际交期。
- 售后抽取首批5个可追溯工单。
- 对证据不足项目标记 `INSUFFICIENT`，不等待“完美资料”。

### 第4周

- 运行校验脚本。
- 形成首版价格、交期、供应和资格边界。
- 只更新达到门槛的结论；其余任务保留下一步和责任人。
