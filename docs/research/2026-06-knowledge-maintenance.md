# 竞争产品知识更新机制

更新日期：2026-06-09

## 1. 目标

把公开研究、产品资料、真实报价、项目输赢和售后经验维护成同一套可追溯知识，而不是依赖个人记忆或一次性报告。

## 2. 知识对象

| 对象 | 权威输入 | 更新触发 |
|---|---|---|
| 产品族与系列 | 官网、目录、数据表 | 新品、停产、改版 |
| 技术参数 | 当前数据表和订货代码 | 版本或配置变化 |
| 认证与合规 | 证书/声明原件 | 到期、范围、材料变化 |
| 中国供应 | 供应链、订单和正式交期 | 产地、库存、交期变化 |
| 价格 | 可比报价、成交数据 | 新项目或价格政策变化 |
| 客户认可 | 项目、审计和访谈记录 | 输赢、验证、故障或扩单 |
| 售后表现 | 工单、备件和服务记录 | 故障、维修和SLA变化 |

## 3. 更新节奏

### 每个项目结束后

- 销售填写 `2026-06-competitive-project-log-template.csv` 对应记录。
- 使用 `validation_ids` 将项目关联到一个或多个内部验证任务。
- 应用工程核对型号、工况和参数是否真正可比。
- 产品经理区分事实、客户观点和内部推断。
- 输赢原因没有客户或项目证据时，标记低可信度。
- 原始文件进入公司批准的受控文档库，Git只记录证据索引和摘要。

### 每月

- 汇总新竞争型号、报价、交期和客户问题。
- 检查是否出现相互矛盾的项目记录。
- 复核 `2026-06-internal-evidence-intake.csv` 中的 `PENDING` 记录。
- 对证据错误或不足的记录明确标记 `REJECTED` 或 `INSUFFICIENT`。
- 更新战卡中的客户发现问题，不因一个案例调整威胁等级。

### 每季度

- 每家竞品至少复核一次官网、重点产品页和中国业务信号。
- 至少选择三个可比项目分析价格和交期。
- 用真实项目替换知识自测中的一个场景。
- 汇总30天训练或季度复训的模块成绩、致命错误和补强结果。
- 复核威胁等级和可信度，二者分别更新。

### 每年

- 重做一级产品线地图和中国组织布局。
- 清理停产产品、失效链接和过期证书。
- 评估产品路线、渠道策略和重点行业是否变化。

## 4. 角色分工

| 角色 | 责任 |
|---|---|
| 战略/产品经理 | 维护分类、证据规则、战卡、威胁判断和行动建议 |
| 销售 | 提供报价、客户标准、竞争型号和可验证输赢原因 |
| 应用工程 | 核对工况、选型、可比性和技术风险 |
| 供应链 | 确认产地、库存、承诺与实际交期 |
| 售后 | 提供故障、备件、响应和维护体验 |
| 市场 | 将已验证能力转化为案例、内容和销售工具 |

## 5. 质量门槛

以下情况不得升级为正式竞争结论：

- 没有具体竞品系列或型号。
- 参数比较缺少介质、压力、温度或连接等关键工况。
- 价格缺少数量、币种、贸易条款或配置。
- 交期只记录销售承诺，没有订单或实际到货验证。
- 客户名称或案例来自未经确认的宣传。
- 认证只看到图标或文字，没有适用范围。

## 6. 熟练度仪表

每季度按团队记录以下指标：

| 指标 | 初始目标 |
|---|---:|
| 四家公司代表系列口头识别正确率 | ≥90% |
| 卫生阀比较字段完整率 | ≥90% |
| 竞争项目具体型号记录率 | ≥80% |
| 输赢原因有证据支持比例 | ≥70% |
| 价格/交期记录具备可比条件比例 | ≥60% |
| 战卡季度更新完成率 | 100% |
| 自测达到75分以上人员比例 | ≥80% |

这些是知识管理目标，不是市场份额或销售绩效目标。初始目标运行两个季度后，再根据数据质量调整。
